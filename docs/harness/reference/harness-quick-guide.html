Souzip 하네스 — 쉬운 설명

워크플로 · 스킬 · 스크립트 · 문서가 뭔지, 몇 개인지만 정리했습니다.

30초 요약

하네스 = AI에게 “지금 뭘 하고, 뭘 하면 안 되는지” 알려 주는 레포 안 설명서 + Cursor 설정입니다.
코드를 대신 실행하는 프로그램이 아니라, 규칙과 순서입니다.

용어 맵 — “그게 뭐냐” → “우리 레포에 뭐가 있냐”

들어본 말Souzip에 실제로 있는 것없음 / 나중
워크플로 5단계 순서 + md 2개 (00-triggers, 01-session-lifecycle) —
스킬 (Skill) Cursor souzip-* 6개 —
규칙 (Rule) 00-souzip-harness.mdc 1개 (항상 적용) —
훅 (Hook) — 아직 없음 (세션 자동 실행 스크립트 등은 미설정)
스크립트 preflight.sh 1개 (tuist 기준선) —
문서 AGENTS.md + docs/harness/ + docs/plans/ —

워크플로 — “기능 하나” 할 때 순서

이름만 외우면 됩니다: 받기 → 플랜 → 구현 → 검증 → 배포

1
intake (선택) — 범위 정하기
당신: “위시리스트 UI 만들고 싶어”
AI: 질문 1개씩 · 코드 ❌
↓
2
plan — 설계서 쓰기
당신: “플랜만 작성해줘” / “메모 반영해서 업데이트해”
AI: docs/plans/…/plan.md · 코드 ❌ · 승인 대기
↓
3
implement — 코드 짜기
당신: 「구현해」 (이 말 전엔 코드 금지 = G1)
AI: preflight → plan대로만 수정
↓
4
verify — 점검
당신: “리뷰해”, “검증해”
AI: 레이어·plan 범위·증거 기록 · “완료” 남발 ❌
↓
5
ship — git
당신: 「커밋해」「PR 만들어줘」 (명시할 때만 = G4)
AI: 커밋·gh pr · base develop

짧은 작업 (Quick Flow)

오타·한 줄 버그 → plan 없이 바로 implement 가능. 새 화면·Factory·레이어 건드리면 무조건 Full (위 5단계).

스킬 6개 (Cursor만)

채팅할 때 비슷한 말을 하면 Cursor가 해당 스킬을 골라 읽게 합니다. 본문은 짧고, 자세한 건 md 링크.

스킬언제하는 일
souzip-harness 하네스가 뭐냐, 어떻게 쓰냐 progress + triggers 읽고 모드 안내
souzip-intake 큰 기능, 범위부터 질문으로 범위 좁히기 · 코드 ❌
souzip-plan 플랜, 리서치, 메모 반영 plan.md 작성 · G1
souzip-implement 구현해 preflight → plan 구현
souzip-verify 리뷰해, 검증해 체크리스트 + 증거
souzip-ship 커밋해, PR G4 지킬 때만 git

경로: .cursor/skills/souzip-*/SKILL.md

규칙 1개 · 훅 0개

Rule — 00-souzip-harness.mdc

매 채팅마다 자동으로 켜짐 (alwaysApply). “plan 전 코드 금지”, “PR은 말할 때만” 같은 한 줄 요약.

Hook — 없음
예: “채팅 시작할 때마다 preflight 자동 실행” 같은 건 아직 안 붙여 둠. 지금은 AI가 스킬·AGENTS를 읽고 스스로 preflight 하라고 적혀 있을 뿐입니다.

스크립트 1개

파일누가언제하는 일
docs/harness/scripts/preflight.sh 당신 또는 AI (터미널) implement 직전 tuist install + tuist generate — 실패하면 새 기능 말고 기준선부터

문서 구조 — 딱 3덩어리만 기억

① 진입 (1파일)
AGENTS.md (프로젝트 루트)
  • 세션 시작할 때 뭐 읽을지
  • 끝났다의 기준 (DoD)
  • 세션 끝날 때 뭐 적을지
② 하네스 = 공통 규칙 (docs/harness/)
  • progress.md — 지금 뭐 하다 말았는지 (세션 메모)
  • workflows/00-triggers.md — 5모드·게이트 정본
  • constitution.md — 금지 사항 (!, Combine…)
  • context/ — Tuist, 아키텍처
  • scripts/preflight.sh — 기준선
  • scratch/ — 임시 메모 (git 제외)
③ 기능별 작업 (docs/plans/위시리스트/ …)
  • plan.md — Before/After, 완료 기준
  • feature-tracker.json — (큰 기능만) 상태·증거
  • prd, milestones — 있으면
AGENTS.md          ← 항상 먼저
    ↓
docs/harness/      ← 공통 (모든 기능에 같음)
    ↓
docs/plans/OOO/    ← 이번 기능만

새 Cursor 채팅 — 실제로 일어나는 일

  1. Cursor가 Rule + 말에 맞는 Skill을 붙임
  2. AI가 AGENTS.md → progress.md 읽음
  3. 기능 작업이면 docs/plans/…/plan.md 읽음
  4. 「구현해」면 preflight 후 코드 수정
  5. 끝나면 progress에 한 줄 (당신이 시키거나 AI가 제안)

당신이 쓸 말만 (치트시트)

  • 「플랜만 작성해줘」 → plan, 코드 없음
  • 「메모 반영해서 업데이트해」 → plan만 수정
  • 「구현해」 → implement (그 전엔 코드 X)
  • 「리뷰해」 → verify
  • 「커밋해」「PR 만들어줘」 → ship
