# 막아야 하는 조건

AI가 혼자 넘으면 안 되는 선입니다.

## 코드 전

- Goal 문서 없이 Story를 확정하지 않습니다.
- Goal 문서에는 성공 기준, 하지 않을 것, Story 후보, 최종 합의가 있어야 합니다.
- Story 분리안은 사용자 확인 후 확정합니다.
- Plan은 사용자 승인 후 구현합니다.
- 사용자가 “구현해”라고 하기 전에는 코드를 고치지 않습니다.

## 구현 중

- Plan에 없는 요구가 생기면 Plan을 먼저 고칩니다.
- Plan 범위 안의 검증 실패는 AI가 고치고 다시 검증할 수 있습니다.
- Tuist, Factory, 모듈 경계, 레이어 규칙처럼 큰 변경이 필요하면 멈추고 사용자에게 묻습니다.

## 끝낼 때

- Plan은 검증 결과가 있어야 닫을 수 있습니다.
- 완료라고 말하려면 방금 실행한 검증 명령과 결과가 있어야 합니다.
- 생략한 검증은 이유를 남겨야 합니다.
- Story는 관련 Plan이 끝난 뒤 PR 하나로 마무리합니다.
- PR 전에는 `base_commit..origin/develop` 변경 파일과 `base_commit..HEAD` 변경 파일이 겹치는지 확인합니다.
- 변경 파일이 겹치면 멈추고 사용자에게 알립니다.
- commit은 사용자가 “커밋해”라고 한 뒤에만 합니다.
- PR 생성과 PR 생성을 위한 push는 사용자가 “PR”이라고 한 뒤에만 합니다.
