# Subagents

서브에이전트는 먼저 독립된 세션으로 메인 대화를 깨끗하게 유지하기 위해 씁니다.
병렬 작업은 나중에 필요할 때 붙입니다.

## Workflow agents

| agent | 주 역할 | 유형 |
|-------|---------|------|
| `researcher` | 레퍼런스와 로컬 문서 조사 | 독립형, 필요 시 병렬형 |
| `interviewer` | 요구사항 인터뷰와 Goal 초안 | 독립형 |
| `story-splitter` | Goal을 PR 단위 Story로 나누기 | 독립형 |
| `planner` | Story를 세션 단위 Plan으로 나누기 | 독립형 |
| `implementer` | 승인된 Plan 구현 | 독립형 |
| `verifier` | 검증과 실패 분류 | 독립형, 필요 시 병렬형 |

## 기본 규칙

- 메인 세션은 사용자 합의, 범위 판단, 최종 선택을 맡습니다.
- 서브에이전트는 메인 세션이 준 입력 밖으로 결정을 확장하지 않습니다.
- 같은 Story 안에서 여러 구현 에이전트를 동시에 돌리지 않습니다.
- 병렬은 먼저 조사와 검토처럼 읽기 중심 작업에만 씁니다.
- 구현 병렬은 서로 다른 Story worktree가 안정된 뒤에만 검토합니다.
- 구현하지 않는 역할은 파일을 고치지 않습니다.
- 결과는 결론, 근거, 추천안, 리스크, 남은 질문 순서로 돌려줍니다.

## 호출 입력

서브에이전트에는 아래를 함께 줍니다.

- 맡길 역할
- 현재 Goal, Story, Plan 위치
- 허용된 파일과 금지된 파일
- 사용할 레퍼런스나 문서
- 검증 기준
- 멈춰야 하는 조건
- 결과 형식

## 실행 형식

지금은 `.agents/agents/*.md`를 역할 설계 문서로 둡니다.
나중에 Codex project custom agent로 실행해야 하면 `.codex/agents/*.toml`로 옮깁니다.

## 승인 기준

- 조사 결과는 메인 세션이 요약합니다.
- Goal 초안, Story 분리안, Plan 초안은 사용자 확인 후 확정합니다.
- 구현은 사용자가 “구현해”라고 말한 뒤 시작합니다.
